# Hardening and verification matrix

Capture both guests after functional seed and join, before applying any hardening. The configuration collector records the initial and final facts listed below. The [assessment record](assessment.md) contains the current observation status for each control. Runtime checks are required where the table calls for access or protocol evidence.

| Control | Initial configuration to capture and its risk | Remediation | Verification and evidence | Remaining limitations |
| --- | --- | --- | --- | --- |
| C01 Domain password policy | Current domain length, history, complexity, password age and reversible encryption. Weak defaults increase password guessing and reuse | 14 or more characters, 24-password history, complexity on, minimum age one day and reversible encryption off. Align Default Domain Policy | Read `Get-ADDefaultDomainPasswordPolicy` after refresh. Capture values in both DC reports | Human quality and breached-password screening are outside this check. Fine-grained policies are inventoried |
| C02 Account lockout | Threshold, duration and observation window. Unrestricted retries increase guessing exposure | Threshold 10, duration and reset window 15 minutes | Measure the domain policy. An optional supervised test may lock only a disposable account and confirm event 4740 | Lockout allows denial of service and is separate from multifactor authentication |
| C03 Privileged membership | Direct and effective membership across eight sensitive groups. Unexpected nesting gives persistent administrative access | Maintain the named directory administrator, separate helpdesk account and reserved emergency identity. Review drift before removing it | Verify group SID allowlists, eligible direct members, recursive leaves and protected account attributes | Eight groups provide a bounded review. This does not enumerate every extended right or logon path |
| C04 Computer creation quota | Existing domain machine account quota, often 10 in a new forest. Ordinary users may create unmanaged computer accounts | Set default quota to zero after the approved join | Read `ms-DS-MachineAccountQuota` on the domain object and retest the existing secure channel | An explicitly delegated join right can still grant creation. Existing machines remain joined |
| C05 LDAP signing | Effective DC and client signing values. Unsigned directory requests lack message integrity | Refresh the signing-required client policy first. Then require DC signing | Capture all three registry settings and run the Kerberos signed LDAP bind as a department user | Legacy simple binds require transport changes. TLS and channel binding are distinct checks |
| C06 SMB server signing | DC require-signing setting. Clients that accept unsigned traffic can face tampering | Require SMB server signatures on the DC | `Get-SmbServerConfiguration` and working SMB and SYSVOL access after policy refresh | Signing provides integrity. SMB encryption is a separate control |
| C07 SMB client signing | Effective workstation require-signing setting. An unsigned server is unsuitable for sensitive access | Require signing for the pilot client. Some Windows 11 builds already require it | `Get-SmbClientConfiguration` and successful authenticated share access | Record a preexisting pass as a retained control |
| C08 NTLM | LM compatibility level and configured incoming/domain audit. Legacy responses and poor visibility obstruct migration | Apply level 5, audit incoming NTLM and audit domain NTLM without broad NTLM blocking | Check DC and client settings and review the NTLM Operational log during representative workflows | This policy permits NTLMv2 fallback. A quiet log over a short window cannot establish elimination |
| C09 Windows Firewall | Effective profile state and inbound defaults. Unnecessary reachability expands exposure | Enable all profiles and explicitly block inbound connections by default while keeping needed role rules | Query ActiveStore and rerun DNS, SYSVOL, secure channel and signed SMB access | A profile check alone cannot inventory every inbound rule |
| C10 Defender | Antimalware and real-time protection state, including signature age. A disabled scanner misses file inspection | Enable real-time protection through the pilot GPO if Defender is active | Query `Get-MpComputerStatus` locally after refresh | Tamper protection, update age and coexistence with other products need separate review |
| C11 Workstation RDP | Effective Remote Desktop state and listener. A needless network logon endpoint increases exposure | Disable RDP through the workstation GPO and administer from the console | Confirm the effective deny value and no listener on the configured RDP port | Local console and other authorized management channels remain available |
| C12 Advanced audit policy | Effective logon, user/group management and Kerberos service ticket masks. Weak logs hide unauthorized changes | Use the force-subcategory policy and enable the selected success/failure subcategories | Capture `auditpol` masks. Correlate successful logon 4624, CIFS TGS 4769 and disposable password reset 4724 where generated | Local retention limits reconstruction. DS object-change events also require matching SACLs |
| C13 Department access | Share ACL, NTFS ACL and both group nesting chains. Excess permissions expose fictional departmental data | Seed the secure shares at deployment. Retain protected ACLs, with the departmental domain-local groups granting Change and Modify | Configuration compares both ACLs and group chains. As each employee, write and delete a fixture in the allowed share and receive Access Denied in the other | Other resources and custom file-level ACL drift need separate review |
| C14 Helpdesk delegation | ACLs on modeled OUs and the inherited reset right on both disabled fixtures. Broad delegation can expose protected users | Add one Reset Password ACE for descendant user objects in People | Check the expected inherited ACE and use the delegated account against both disabled fixtures before and after | Selected scopes are reviewed, and the exercise covers password reset alone |
| C15 Managed service identity | Presence, service group, encryption types and retriever set. Static credentials and broad retrieval expose service identities | Stage an outbound-only gMSA with AES, no SPNs and an empty dedicated retriever group | Inspect the effective AD object and retriever list. Capture no managed password | No live service workload runs in this pilot. Install and test on an authorized member service host when one exists |
| C16 Windows LAPS | Schema, policy, encrypted backup existence, and recent success event. Reused local admin passwords increase lateral reach | Extend only the disposable forest schema where needed. Scope encrypted backups and computer SELF rights to Workstations | Collect workstation policy and event 10018. Use an AD presence query for the encrypted attribute, without retrieving the secret | Requires supported OS updates, DFL 2016 or later and access to query the attribute presence. A recovery drill remains separate |

Default Domain Policy controls C01 and C02 centrally. In GPMC edit **Computer Configuration → Policies → Windows Settings → Security Settings → Account Policies** and align Password Policy and Account Lockout Policy with the dedicated target. Confirm the AD values after another policy refresh. Export the baseline and record prior settings before changing them. The lab scripts also apply the AD attributes directly.

Registry-backed GPO entries under `SYSTEM` can persist after unlink. Restore each recorded value with a targeted policy or supported administrative command, refresh both guests and rerun health checks. Avoid weakening a preexisting setting merely to create a visible delta.
